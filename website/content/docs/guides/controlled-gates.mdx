`cu`, `cu3`, `cp`, `crx`, `cry`, `crz` and `r1` are native IR gates in
Superfermion — they simulate, differentiate and serialize exactly, without
decomposition.

## Controlled-U3: cu / cu3

`circuit.cu(theta, phi, lam, control, target, gamma=0.0)` (alias `cu3`)
applies a controlled U3 rotation with Qiskit's optional gamma phase:

**`CU = diag(I, e^{iγ}·U3(θ, φ, λ))`**

— the same control-first layout as Qiskit's `CUGate`. `gamma` defaults to
`0`, which reproduces the original controlled-U3 (and PennyLane's `qml.CU`),
so existing calls are unchanged:

```python
import superfermion as sf

qc = sf.Circuit(2).cp(0.7, 0, 1).cu(1.2, 0.3, 0.4, 0, 1)
state = sf.simulate(qc)
print(state.numpy().round(4))
# [1.+0.j 0.+0.j 0.+0.j 0.+0.j]  (control in |0> -> CU leaves |00> alone)
```

With the control qubit in |0⟩ the `CU` acts as identity, so the state
stays |00⟩. Flip the control to see the U3 branch:

```python
qc2 = sf.Circuit(2).x(0).cu(1.2, 0.3, 0.4, 0, 1)
sv = sf.run(qc2, shots=0).statevector
# <Z> = P(0) - P(1) = -1.0 on the |1> control, so it stayed |1>
print(sf.expval(sv, sf.PauliString("ZI", coeffs=1.0)))  # -1.0
```

The gates accept symbolic parameters like any other rotation, work
with gradients, and are preserved by `compile()` optimization passes.

### Qiskit gamma phase

`cu` accepts Qiskit's fourth `gamma` parameter — a phase `e^{iγ}` on the
control-1 subspace. `from_qiskit`/`to_qiskit` map it **natively** (the gate
is no longer routed through a lossy matrix fallback):

```python
from qiskit import QuantumCircuit
from superfermion.bridge import from_qiskit

qc = QuantumCircuit(2).cu(0.7, 0.3, 0.2, 0.9, 0, 1)   # theta, phi, lam, gamma
sf_qc = from_qiskit(qc)              # imports as a native CU gate
# equivalent, all-native Superfermion form:
sf_qc = sf.Circuit(2).cu(0.7, 0.3, 0.2, 0, 1, 0.9)   # gamma is last here
```

## Controlled-phase: cp

`circuit.cp(phi, control, target)` applies the phase-controlled
`CP(phi) = diag(1, 1, 1, e^{i phi})` gate:

```python
qc3 = sf.Circuit(2).x(0).x(1).cp(0.7, 0, 1)
sv = sf.run(qc3, shots=0).statevector
print(sv[3])   # ~ (0.764842+0.644218j) = e^(i*0.7) on |11>
```

## Controlled rotations: crx, cry, crz

`circuit.crx(theta, control, target)`, `cry(...)` and `crz(...)` apply the
rotation on the target only when the control is |1⟩:

**`crx/cry/crz = diag(1, 1) ⊕ R(θ)`** — *not* the same as `cp`:

```python
import superfermion as sf
import numpy as np

qc = sf.Circuit(2).x(0).crz(0.4, 0, 1)
print(np.round(sf.run(qc, shots=0).statevector, 4))
# [0.+0.j  0.9801-0.1987j  0.+0.j  0.+0.j] -> e^{-iθ/2}
# (index 1 is the state whose qubit 0 — the control — is set)
```

`crx` and `crz` map to their own opcodes. The IR has no `CRy` opcode, so
`cry(θ)` is emitted as `cu(θ, 0, 0)`, which is *exactly* `CRy`: `U3(θ,0,0)`
is `Ry(θ)` and a controlled block keeps the phase.

```python
# These two produce the identical statevector, bit for bit
sf.Circuit(2).x(0).cry(0.4, 0, 1).to_unitary()
sf.Circuit(2).x(0).cu(0.4, 0.0, 0.0, 0, 1).to_unitary()
```

The difference from `cp` matters: `crz(θ) = diag(1, 1, e^{-iθ/2}, e^{iθ/2})`
while `cp(θ) = diag(1, 1, 1, e^{iθ})`. They differ by a relative phase on the
`|10>` branch, so do not substitute one for the other.

All four are differentiable on both exact paths (adjoint and
parameter-shift) — see the [gate coverage table](/docs/guides/gradients#gate-coverage-and-correctness).

## Phase gates: p and r1

`circuit.p(phi, qubit)` and `circuit.r1(phi, qubit)` build the **same matrix**,
`diag(1, e^{iφ})`. `r1` exists so that OpenQASM and Qiskit-style code ports over
unchanged; the IR stores it under its own opcode and both differentiate
identically.

```python
np.allclose(
    sf.Circuit(1).p(0.7, 0).to_unitary(),
    sf.Circuit(1).r1(0.7, 0).to_unitary(),
)   # True
```

Neither is `rz`: `rz(φ) = diag(e^{-iφ/2}, e^{iφ/2})` differs by a global phase,
which is invisible in a statevector but *is* visible if you compare unitaries.

## Serialization round-trips

DAG serialization preserves every controlled gate, including `CP` and
`CU`. Converting a circuit to a `QuantumDAG`, dumping it to JSON and
loading it back yields an identical statevector:

```python
dag = qc.to_ir()
dag2 = type(dag).from_json(dag.to_json())

sv1 = dag.simulate()
sv2 = dag2.simulate()
print(max(abs(a - b) for a, b in zip(sv1, sv2)))   # 0.0
```

Earlier builds of the Rust IR silently **dropped** `CP` gates on this
round-trip (and `cu` was rejected with "Unknown gate: cu"); both now
survive unchanged. The same holds for `crx`, `cry`, `crz` and `r1` through
OpenQASM 3 — see [Framework Interop](/docs/guides/interop#openqasm-30).
