Welcome. This page gets you from zero to a running quantum circuit with gradients.

## 1. Install

```bash
pip install superfermion
```

That's it. Python 3.10 or newer on Linux, macOS, or Windows. The wheels are
built once against the CPython stable ABI and tagged `cp310-abi3`, so one
binary per platform serves 3.10 through 3.15 — no Rust toolchain required.

| Platform | Architectures | Wheel tag |
| --- | --- | --- |
| Linux | x86_64, aarch64 | `manylinux_2_28` (glibc 2.28+, i.e. RHEL 8+, Ubuntu 20.04+, Debian 10+) |
| Linux (musl) | x86_64, aarch64 | `musllinux_1_2` (Alpine 3.15+) |
| macOS | universal2 (Intel + Apple Silicon) | `macosx_10_12_universal2`, plus `macosx_11_0_arm64` |
| Windows | amd64, arm64 | `win_amd64`, `win_arm64` |

Anything outside that table — PyPy, 32-bit targets, older glibc, other
architectures, free-threaded builds — is compiled from the source distribution
by `pip` and needs Rust 1.85+ and ~3 GB of free disk.

### What a `pip install` does not give you

Three structural limits, all of which fail loudly rather than degrading
silently:

**CUDA.** The GPU backend is a Rust feature, not a Python extra, so no
published wheel contains it. `sf.run(..., device="gpu")` raises immediately
with `GPU not available. Diagnostic: GPU feature not compiled`. Build it
yourself with `maturin develop --release --features gpu` (CUDA 12 toolkit and a
matching driver required). The `[gpu]` extra is unrelated — it installs JAX
with CUDA for the QML layers and adds no CUDA simulator.

**crates.io.** The Rust crates (`sf-ir`, `sf-cat`, `sf-qec`, `sf-pulse`,
`sf-router`, `sf-compiler`, `sf-gpu`, `sf-bindings`) are workspace members, not
published packages. There is no `cargo add sf-ir`; the Rust API ships only as
the `_sf_core` extension module inside the Python wheel.

**Free-threaded CPython (3.14t, 3.15t).** No limited API exists for
free-threaded builds before 3.15, so no `cp314t` wheel is published. `pip`
falls back to the sdist and pyo3 emits a version-specific extension instead of
an `abi3` one. The CI lane that runs this is advisory (`continue-on-error`),
so treat free-threaded support as best-effort rather than gated.

## 2. Verify

```python
import superfermion as sf
print(sf.__version__)  # e.g. '0.1.5'
```

## 3. Build a circuit

```python
import superfermion as sf
import sys

# Unicode diagrams on Windows consoles: reconfigure stdout first
sys.stdout.reconfigure(encoding="utf-8", errors="replace")

# Bell state: entangle two qubits
qc = sf.Circuit(2).h(0).cx(0, 1)
print(qc.draw())
# q0: ── H ── ● ──
# q1: ────── X ──
```

Every gate method returns the circuit — chain as many as you want.

## 4. Run it

```python
result = sf.run(qc, shots=1024)
print(result.counts)  # {'00': ~512, '11': ~512}
```

`sf.run()` works everywhere — local CPU, GPU, IBM Quantum, IonQ. Same API.

## 5. Get the quantum state

```python
state = sf.simulate(qc)       # returns sf.State (Rust-native)
print(state.numpy())           # [0.707+0j, 0, 0, 0.707+0j]
print(state.entropy())         # 0.0
print(state.purity())          # 1.0
```

`sf.State` lives in Rust. All methods — `expectation()`, `grad()`, `sample()` — dispatch to compiled Rust.

## 6. Compute an expectation value

```python
from superfermion import Hamiltonian, PauliString

H = Hamiltonian([PauliString("ZZ", coeff=1.0)])
energy = H.expectation(state.numpy())
print(energy)  # 1.0

# Or pass the Rust observable format directly to State:
# state.expectation([([3, 3], 1.0, 0.0)])   # ZZ: 0=I 1=X 2=Y 3=Z (LSB-first)
```

## 7. Take a gradient

```python
theta = sf.param("theta")
qc = sf.Circuit(1).ry(theta, 0)

state = sf.simulate(qc, params={"theta": 0.5})
obs = [([3], 1.0, 0.0)]      # Pauli Z
dag = qc.to_ir()  # keep parameters symbolic — .bind() would erase them
grads = state.grad(obs, dag, {"theta": 0.5})

print(grads)  # {"theta": -0.479...}
```

The adjoint method computes gradients in one backward pass regardless of parameter count. On 20-qubit SU(2) circuits it is ~77x faster than parameter-shift at 40 parameters and ~73x at 80, because parameter-shift needs two circuit runs per parameter. Full grid and correctness checks: [gradient benchmarks](/docs/reference/performance#adjoint-differentiation).

## 8. Try a different simulation method

```python
# MPS — for weakly entangled circuits, scales to 200+ qubits
qc_mps = sf.Circuit(8).h(0)
for i in range(7):
    qc_mps = qc_mps.cnot(i, i + 1)
result = sf.run(qc_mps, method="mps", bond_dim=64, shots=1024)
print(result.counts)  # {'00000000': ~512, '11111111': ~512}

# Stabilizer — for Clifford-only circuits, scales to 1000+ qubits
qc_stab = sf.Circuit(100).h(0)
for i in range(99):
    qc_stab = qc_stab.cnot(i, i + 1)
result = sf.run(qc_stab, method="stabilizer", shots=1024)
print(list(result.counts.items())[:2])

# Density matrix — for noisy simulation
qc_noisy = sf.Circuit(1).x(0)
noise = sf.NoiseModel().add_depolarizing(0.01)
result = sf.run(qc_noisy, method="density_matrix", noise_model=noise, shots=0)
print(f"purity = {result.metadata['purity']:.4f}")
```

## Staying up to date

`pip install superfermion` installs the newest release it can resolve, but pip
never moves an environment that already holds an older one. To pull an existing
install forward:

```bash
pip install -U superfermion
```

From 0.1.20 onward, importing the package checks PyPI at most once a day and
prints a single line to stderr when a newer release exists:

```
[superfermion] 0.1.20 is installed; 0.1.21 is available (pip install -U superfermion)
```

The check runs in a background thread, so import never waits on the network, and
it stays silent when offline, inside CI, and under pytest. Switch it off with
`SF_NO_UPDATE_CHECK=1` (or `NO_UPDATE_NOTIFIER=1`); the answer is cached in
`%LOCALAPPDATA%\superfermion\update_check.json` on Windows and
`~/.cache/superfermion/update_check.json` elsewhere.
