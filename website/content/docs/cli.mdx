# Superfermion CLI Reference

> Complete reference for every `sf` subcommand.

The CLI is invoked as `sf ...` when installed (`pip install -e .`), or as
`python -m superfermion.cli ...` anywhere else. Both forms accept the same
subcommands and arguments.

**26 commands available:** `info`, `version`, `backends`, `validate`, `run`,
`benchmark`, `shor`, `vqe`, `qaoa`, `chemistry`, `qec`, `compile`, `transpile`,
`noise`, `gradient`, `train`, `circuit`, `statevector`, `qpu`, `config`,
`plugin`, `auth`, `convert`, `estimate`, `compare`, `jobs`.

---

## Global behaviour

- Every invocation first prints a coloured ASCII banner (stderr-safe on
  Windows — stdout is auto-reconfigured to UTF-8 at startup). Use `--no-banner`
  or set `SF_NO_BANNER=1` to suppress.
- Exit codes follow the Unix convention: `0` on success, `1` on command
  failure. `validate` is the only subcommand that returns non-zero on
  partial failure; every other subcommand returns `0` unless argparse
  rejects the arguments.
- Network commands (`qpu`, `jobs`, `transpile --submit`) require provider
  credentials configured via `sf auth login` or environment variables.

## `sf info`

Dumps the installed SuperFermion version, Python version, platform,
detected runtime environment, JAX backend + devices, registered backends,
and a list of top-level modules with one-line descriptions.

```bash
sf info
```

No arguments.

---

## `sf version`

Prints SuperFermion + Python + JAX + Flax + Optax version strings. Shorter
than `sf info`, suitable for bug reports.

```bash
sf version
```

---

## `sf backends`

Lists every backend name registered in
[`superfermion/backends/registry.py`](../superfermion/backends/registry.py).
Use this before `sf run --backend=…`.

```bash
sf backends
```

See [backends.md](backends.md) for descriptions and tradeoffs of each
entry.

## `sf validate`

Runs nine end-to-end smoke tests covering core import, JAX-differentiable
circuits, VQE, QAOA, serialization, visualisation, environment detection,
QDL, and QLLM. Typical runtime is ~25s.

```bash
sf validate
```

Exit code: `0` if all nine pass, `1` otherwise. Each check prints
`[PASS] <name> (<seconds>)` or `[FAIL] <name>: <error>`.

## `sf run <file>`

Execute a circuit stored as JSON (the format produced by
`sf.Circuit.to_json()`).

```bash
sf run circuit.json --backend=jax --shots=4096
```

| Argument | Default | Description |
|----------|---------|-------------|
| `file` (positional) | — | Path to the circuit JSON file. |
| `--backend` | `simulator` | Name from `sf backends`. |
| `--shots` | `1024` | Number of measurement samples. |

Output:
- Qubit count / gate count / depth / chosen backend / shot count.
- Wall-clock time in ms.
- Measurement histogram (`{bitstring: count}`).
- Results saved alongside the input as `<name>_result.json`.

### Circuit-JSON schema

```jsonc
{
  "n_qubits": 2,
  "n_cbits":  2,
  "name":     "bell",
  "parameters": {},                     // optional: bound parameter values
  "gates": [
    {"name": "H",       "qubits": [0]},
    {"name": "CNOT",    "qubits": [0, 1]},
    {"name": "MEASURE", "qubits": [0], "classical_bits": [0]},
    {"name": "MEASURE", "qubits": [1], "classical_bits": [1]}
  ]
}
```

`name` values accepted by the parser follow the Circuit gate methods:
`H, X, Y, Z, S, SDG, T, TDG, SX, I, RX, RY, RZ, P, U (or U3), CX/CNOT,
CZ, CY, CP, SWAP, ISWAP, ECR, RXX, RYY, RZZ, CCX/TOFFOLI, CSWAP/FREDKIN,
MEASURE, BARRIER, RESET`.

Produce a valid file in one line:

```bash
python -c "import superfermion as sf, pathlib; c=sf.Circuit(2).h(0).cx(0,1); pathlib.Path('bell.json').write_text(c.to_json())"
```

## `sf benchmark`

Sweep circuit sizes and measure JIT-compile + per-call execution time on
the default JAX backend.

```bash
sf benchmark --qubits 10 --iterations 50
```

| Argument | Default | Description |
|----------|---------|-------------|
| `--qubits` | `10` | Largest qubit count to test. The sweep includes 2, 4, 6, 8, 10, and your value (deduped). |
| `--iterations` | `50` | Timed repetitions per size; JIT time is measured once. |

Output columns: `Qubits  Gates  JIT Time  Exec Time  States`.

## `sf shor`

Post-process raw measurement bitstrings from Shor's algorithm into
candidate factor pairs using continued-fraction expansion.

```bash
sf shor 0100,1000 --N 15 --a 7
```

| Argument | Default | Description |
|----------|---------|-------------|
| `measurements` (positional) | — | Comma-separated binary strings produced by the phase-estimation register. |
| `--N` | `15` | Integer to factor. |
| `--a` | `7` | Generator coprime to `N`. |

Output: table of `Binary | Phase | Period r | Factors`. Computation is
purely classical (JAX-accelerated GCD) — no QPU is called.

## `sf plugin <action>`

Manage Superfermion plugins (backends, templates, optimization passes).

```bash
sf plugin list              # List all registered plugins
sf plugin list --type backend    # List only backends
sf plugin list --type template   # List only templates
sf plugin install <name>   # Install a plugin from PyPI
sf plugin create <name>    # Create a new plugin scaffold
```

| Argument | Default | Description |
|----------|---------|-------------|
| `action` (positional) | — | `list`, `install`, or `create` |
| `--type` | `all` | Filter by `backend`, `template`, or `pass` |

Plugins can extend Superfermion with custom backends via the `@register_backend`
decorator, templates via `@register_template`, and optimization passes via
`@register_pass`.

## `sf auth <action>`

Manage credentials for quantum hardware providers.

```bash
sf auth login --provider ibm --token <API_TOKEN>
sf auth login --provider ionq --token <API_TOKEN>
sf auth login --provider aws --access-key <KEY> --secret-key <SECRET>
sf auth logout --provider ibm
sf auth status
```

| Argument | Default | Description |
|----------|---------|-------------|
| `action` (positional) | — | `login`, `logout`, or `status` |
| `--provider` | — | Provider name: `ibm`, `ionq`, `aws`, `oq` |
| `--token` | — | API token for IBM/IonQ |
| `--access-key` | — | AWS access key |
| `--secret-key` | — | AWS secret key |

Credentials are stored securely in `~/.superfermion/credentials.json` with
file permissions 0600 on Unix systems.

## `sf convert <input> <output>`

Convert circuit files between formats.

```bash
sf convert circuit.json circuit.sfc    # JSON to native format
sf convert circuit.qasm circuit.json   # QASM to JSON
sf convert circuit.json circuit.qasm   # JSON to QASM
```

| Argument | Default | Description |
|----------|---------|-------------|
| `input` (positional) | — | Input file path |
| `output` (positional) | — | Output file path |
| `--format` | auto | Force output format: `json`, `qasm`, `sfc` |

Supported formats:
- `.json` — Superfermion native JSON (recommended)
- `.qasm` — OpenQASM 2.0
- `.sfc` — Superfermion compact binary format

## `sf estimate <file>`

Estimate QPU execution cost across providers.

```bash
sf estimate circuit.json --backend ibm --shots 1000
sf estimate circuit.json --backend ionq --shots 10000
sf estimate circuit.json --backend aws --shots 1000
```

| Argument | Default | Description |
|----------|---------|-------------|
| `file` (positional) | — | Path to circuit JSON file |
| `--backend` | `ibm` | Provider: `ibm`, `ionq`, `aws` |
| `--shots` | `1024` | Number of shots |

Output includes:
- Estimated cost in USD
- Gate count breakdown
- Estimated queue time
- Optimal QPU recommendation

Pricing models (approximate, check provider for current rates):
- **IBM**: $1.60 per second (Pay-As-You-Go)
- **IonQ**: `0.01 per gate-shot (simulator), `0.15 per gate-shot (QPU)
- **AWS Braket**: `0.30 per task + `0.00015 per shot (simulator)

## `sf compare <file>`

Compare circuit execution across multiple backends.

```bash
sf compare circuit.json --backends statevector,jax,rust --shots 1024
sf compare circuit.json --backends statevector,mps --shots 10000
```

| Argument | Default | Description |
|----------|---------|-------------|
| `file` (positional) | — | Path to circuit JSON file |
| `--backends` | `statevector,jax` | Comma-separated backend list |
| `--shots` | `1024` | Number of shots |

Output includes:
- Execution time per backend
- Result histogram comparison
- Fidelity/correlation between backends
- Best backend recommendation

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Success (or partial success for informational commands) |
| `1` | `sf validate` found at least one failing check, or argparse rejected the arguments |
| `2` | Python-level traceback reached top level (missing module, malformed circuit file, etc.) |

## Troubleshooting

- **`UnicodeEncodeError` when banner prints on Windows** — SuperFermion
  auto-switches stdout/stderr to UTF-8 at startup; if you still hit
  this, set `PYTHONIOENCODING=utf-8` before the call or wrap the banner
  call: all CLI commands are wrapped in `try/except` so any banner
  failure is printed as `(banner suppressed: …)` and the command still
  runs.
- **`File 'foo.json' not found`** — `sf run` expects an absolute or
  cwd-relative path; paths are not searched.
- **`Backend 'xyz' not found`** — run `sf backends` to list the exact
  names. Aliases like `auto`, `simulator`, `ibm`, `aws`, `braket` are
  accepted (see [backends.md](backends.md)).
- **JAX reports "no GPU"** — the default fallback is CPU, which is
  fine for everything except the `cuda` / `cuda_mps` / `cluster`
  backends. Install `jax[cuda12]` to light these up.
